# R 复盘

## 触发

运维按上线手册上线完成，观察期结束。没上线不做 R。

## 步骤

1. 收上线事实：日期、与手册的偏差、上线后验证与观察期结果、回滚与否。写进 `R/R-01-复盘.md`。
2. 从 `S3/S3-02-处理记录.md` 和 S1 走读里，把「实现 / 验收时才发现、S1 没查到」的事实列出来：以后别的需求会用到 → 回填项目手册（公共机制 / 参照功能 / 平台登记清单 / 不可用接口 / 环境），「回填记录」加一行；登记占用标「已上线」。只和本需求有关 → 不回填。
3. 记三个指标（生命周期 › 指标），不评判。对每条 B 类和归因为「设计错」的 C 类，判断是不是 S1 走读、平台取样或 precheck 能提前拦住的；能的话改对应模板的说明文字或加 precheck 项。
4. AC 在线上被推翻的（写得测不出问题），改 S1 模板的 AC 写法说明。
5. 门禁「无法证明」的项上线后出了问题的，写清代价，向用户提一次是否补对应能力（测试依赖、可编译环境、verify 鉴权）。
6. `S2/S2-08-审查.md` 里「后续优化」的安全、实现质量条目列给用户排期，未排期的保留在复盘里。

## 规则

- 只改项目手册、模板说明文字、precheck 三样。不改阶段划分。
- 要改 skill 的，按 SOP约束 执行（先试 precheck 与模板、新增要替换旧条、不写项目专有内容），改完跑 `--lint-sop`。
- 每条回填带出处。

## 产出

`artifacts/{需求}/R/R-01-复盘.md`；项目手册回填；可能的模板 / precheck 改动。

## 出口

项目手册「回填记录」有本需求一行（内容可为「无回填」）。有后续优化时「你要做的」用生命周期 › 当前位置的「R 有后续优化」，否则写「无」，对话最后一条与它一致。
