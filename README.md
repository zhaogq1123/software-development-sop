# sop-v2 — 需求交付 SOP

状态：**v0.9 试运行**。已在真实需求跑到 S2/r1；完整跑完 S3 与 R 后定 v1.0。

## 目标

需求从原文到可上线，交付物满足三条且返工最少：

1. **可编译**：构建环境一次通过。
2. **可部署**：SQL/配置/登记/菜单按手册执行即可，且可重入。
3. **可验证**：每条需求有可操作可观察的 AC，并实际执行过。

门禁七样：编译、单测、precheck、独立审查、交付可用性、环境执行结果、用户明确回复。三态如实记；自造桩结果只算自测。清单/自查是提醒，不是门禁。

问题按类别：**需求不符**、**交付与部署**阻塞上线；**安全**、**实现质量**进后续优化（你排期）。

SOP 硬约束：只写通用流程、无项目专有、篇幅上限、加规则先替换旧规则；`--lint-sop` 机械检查（见 [SOP约束.md](./sop-overview/SOP约束.md)）。

## 阶段

| 阶段 | 做什么 | 出口 |
|------|--------|------|
| S0 | 跨需求事实：仓库地图、共享边界、机制、参照、登记、占用、环境 | 本需求用到的章节存在且有出处 |
| S1 | 判类型；决定表、验收、走读、取样、设计（剧本/路径矩阵/流程图）、待定 | 必问已关；用户确认剧本后确认改动面 |
| S2 | 按改动面写码；`S2/` 只留当前最终态 0→1（迁移/回退进三附或当轮）；出包+门禁 | precheck PASS；可编译则过；审查无阻塞类；门禁如实 |
| S3 | 跑清单，按基线/编译/行为/环境事实分流，再交付循环 | 清单全过；PR 或终包已交 |
| R | 回填手册、记指标、改模板或 precheck | 回填记录有本需求一行 |

类型裁剪、环境形态见 [生命周期.md](./sop-overview/生命周期.md)。出口前自我纠错见 [自我纠错](./sop-overview/生命周期.md)。

## 你要做的事

无前期准备。停下时打开 `artifacts/{需求}/00-当前位置.md`，只做「你要做的」，只看点名的文件。S3 可能是多步短清单（含选择表）；对话末条只发该正文。S3 每带回一轮结果开一个新会话；在真实仓改过代码就带回 `git diff` 导出的文件。对照：[当前位置](./sop-overview/生命周期.md)。

## 导入

把 `sop-v2/sop-*` 拷到 `.cursor/skills/` 或 `~/.cursor/skills/`。导入前可跑 `precheck.py --selftest` 与 `pack.py --selftest`。项目专有检查写 `S0-02-precheck.json` 的 `custom_checks`，不改已安装的脚本（更新 skill 会覆盖）。

## 适用范围

- 流程与技术栈无关；命令占位符，具体写手册「环境」。
- `precheck.py` 专项现绑 Java（Spring/MyBatis-Plus）+ TS/JS/Vue；其他栈仅通用项生效，专项不报也不检，门禁注明「仅通用项」。遇第一个其他栈再按 J1/J2/J3 补检+selftest。
- 中途接手：从 `00-当前位置` 判阶段，整理已有产物为输入，已知缺陷作复现用例，再往下走。
