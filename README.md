# sop-v2 — 需求交付 SOP

状态：**v0.9 试运行**。已在一个真实需求上跑到 S2/r1，据其问题加了独立审查、问题分类、逐条确认、改动面核对、SQL 可重入等检查；完整跑完 S3 与 R 后定为 v1.0。

## 目标

一个需求从原文到可上线，交付物满足三条，且返工轮次最少：

1. **可编译**：代码在构建环境一次编译通过。
2. **可部署**：SQL、配置、登记、菜单按上线手册执行即可，重复执行也不出错。
3. **可验证**：每条需求有能在环境里操作并看到结果的验收条件，并且实际执行过。

门禁六样：编译、单测、`precheck.py`、独立审查、环境里的执行结果、用户的明确回复。每样如实记「通过 / 失败 / 无法证明」——项目关了测试、本机不能编译、某条没执行，就写无法证明，不写通过；执行者对着自造桩跑出的结果只算自测。清单和自查是提醒，不是门禁。

问题按类别处理，不按严重程度：**需求不符**（含需求规定的审批、状态、数据范围被绕过）和**交付与部署**问题阻塞上线；**安全**和**实现质量**问题记入后续优化，不阻塞上线，由你排期。

SOP 本身有硬约束：只写通用流程、不含任何项目或需求专有内容、篇幅有上限、加规则要先替换旧规则，由 `precheck.py --lint-sop` 机械检查（见 [SOP约束.md](./sop-overview/SOP约束.md)）。

## 阶段

| 阶段 | 做什么 | 出口 |
|------|--------|------|
| S0 项目手册 | 跨需求的项目事实：仓库地图、共享边界、公共机制、参照功能、平台登记清单、登记占用、环境。按需建，持续纠正 | 本需求用到的章节存在且有出处 |
| S1 需求与设计 | 判断类型；决定表、需求与验收、参照代码走读、平台数据取样、设计说明、待定决策（必问 / 照先例） | 必问项全部由用户回复；评审通过 |
| S2 实现与交付 | 按改动面写代码（有测试能力时含单测）、提交、precheck、编译、独立审查、交付物 + 可重复执行的 SQL/配置 + 上线手册 + 验证清单 + verify 脚本 + 门禁表 | precheck PASS；能编译的编译通过；审查无阻塞类问题；门禁表如实 |
| S3 验证与修复 | 执行验证清单，结果按 基线/编译/行为/环境事实 分流修复，再交付，循环 | 验证清单全部通过；PR 已建或最终改动包已交付 |
| R 复盘 | 上线后回填项目手册、记指标、改模板或 precheck | 回填记录有本需求一行 |

需求类型决定产出多少：新功能走全套；小改动、线上缺陷、纯配置/数据变更 S1 只写一个 `S1-07-设计.md`，验证一轮。环境形态（能否编译部署、代码是在线仓还是离线快照）由用户在 S1 交付选项里选，执行者在 S2 Step 0 实测核对，只影响交付形式。详见 [sop-overview/生命周期.md](./sop-overview/生命周期.md)。

## 你要做的事

没有前期准备。阶段停下时，打开该需求的 `artifacts/{需求}/00-当前位置.md`，只做「你要做的」那一行写的动作，只看那一行点名的文件。对话最后一条应与这一行一致。对照表在 [生命周期 › 当前位置](./sop-overview/生命周期.md)。

## 导入

把 `sop-v2/sop-*` 六个目录拷到 `.cursor/skills/`（项目级）或 `~/.cursor/skills/`（个人级）。`sop-v2/` 保留为源。导入前可先跑 `python sop-v2/sop-s2-implement-deliver/precheck.py --selftest`。

## 适用范围

- 流程（S0–R、门禁、验证循环、决策分级）与技术栈无关。
- 模板里的编译、测试命令用占位符，具体命令写在项目手册「环境」。
- `precheck.py` 的专项检查目前绑定 Java（Spring 映射注解、MyBatis-Plus `@TableName`）+ TS/JS/Vue 前端技术栈，自测数据和模板示例也按这套栈写。这是技术栈默认，不针对任何具体项目。
  - 其他技术栈：只有通用项生效（交付文件齐全、自测残留、未提交文件、SQL 原文一致与可重入、改动面覆盖、S1 产物结构、审查完整、漏检目录与 patch、遗留待核对标记、manifest）；接口文档与冒烟集合的路径核对依赖 Controller 映射，属专项，专项检查（J1/J2/F1/F2/N1/N2/S1）不会报错也不会生效，门禁表里 precheck 一项要注明「仅通用项」。
  - 专项检查暂不拆成可插拔模块；遇到第一个其他技术栈的项目时，再按 J1/J2 的写法为该栈补检查并加自测用例。
- 中途接手一个已经做了一半的需求：从 `00-当前位置.md` 判断该进哪个阶段，把已有产物整理成该阶段的输入，已知缺陷先作为验证清单里的复现用例，再按本流程往下走。
