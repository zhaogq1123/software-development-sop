# S3 验证与修复

## 目标

每轮比上轮更接近「全部通过」。同一问题不跨两轮结果；一条修复只动锁定的文件。

## 输入

**每轮开新会话**，只读：`00-当前位置`、本轮结果（自跑+带回）、`S3-02`、当前终包 README、`S2-07`、本轮要改的文件。不翻更早轮的对话和 `_archived`。

## 步骤

### 1. 执行与归档

「执行者」自跑；「verify」「手工」由执行人带回。原文存 `S3-01-结果-r{N}.md`。`S3-02` 加 r{N} 节（每轮一节；编号 A-/B-/C-/D- 接上一轮往下编，全文件唯一）。信息不够先处理能判的，缺的进下轮「请补充」。r1 带回编译/单测则回填 S2 门禁表。用户话里的约束当轮落 `D-xx`（需求变更）。

### 2. 先锁范围，再按类分流

遵守自我纠错。**动手前**每条先填满 `S3-02` 一行（产出模板）：「期望」抄用户原话；「改动文件」是本条允许改的全部文件（公共目录按共享边界）；「先例」写同类已有实现的 `文件:行`。**本机验证不了又没有先例→不改**，停「有一个问题」：复述现象与期望，请用户确认或给一份真实文件（页面源码/报错原文/响应样例）。要动表外文件→先补这一行（C3/H7）。

| 类 | 动作 |
|----|------|
| **A 基线** | 不改码、不造远距增量。在线 rebase；离线：选表「其他」软回退打本包全量，同一仓冲突两次→快照刷新。**用户在真实仓改过码，或 preimage 核对不一致**：「你要做的」第 1 步只要 `git diff` 导出的文件，据此同步快照再出包。下包只出全量。手册「环境」更新基线 |
| **B 编译/单测** | 逐条修。能静态查→通用的加 precheck+selftest，项目专有的写 `precheck.json` 的 `custom_checks`（不改已安装的 `precheck.py`）。同类算一条。出包前再扫本轮改过文件同类用法 |
| **C 行为** | 先问题分类（安全/实现质量→`S2-08`「后续优化」）。**漏拦/错文案**：先核识别链是否有已关闭 D；没有→设计错/必问，**禁止补守卫当实现修复**（验证循环）。实现错修码；设计错先改设计（`[S3 修订]`），口径变→待定。用户可推翻归因。不猜 |
| **D 环境事实** | 实际≠设计→回写 S2 sql/config/手册/常量 + 手册「登记占用」。影响口径→待定 |

**同一现象两轮未过**：不再出包。代码回到它出现前最后一次通过的提交；只问一个问题或要一份真实文件，拿到再改。不换方案再试，不扩大改动文件。

### 3. 待定决策一次问

本轮新 `Q-xx` 攒齐一次发。必问未关：相关代码不进下轮，**「你要做的」停在必问态**（不出执行清单混 Q）。其余修复不阻塞。

### 4. 交付下一轮

按 S2 步骤 3–9 出 r{N+1}（含自我纠错与找茬；触及已审查或需求不符→Step 7 复核）。**小修**（只改 `S3-02` 锁定的文件，不动 AC/设计/SQL/配置）只做：提交→`pack.py`→precheck→重写 README 与 `00`；手册、清单其余行、审查不动。README 与 `00` **按模板整份重写**，不在上一轮文本上替换（H7）。**B** 写本轮 `S3-02`，**A** 勾门禁；未过 A 不得更新「你要做的」。差异逐条引本轮编号。清单本轮列：失败重跑+受影响+尚未执行。

三处同文须「S3 短清单」（当前位置）。缺表/粘回/缩写、本轮改过未入步骤、步骤内长文/嵌套=未交付完。数据污染先跑 `reset_test.sql`。

### 5. 收口

清单全过：手册「代码」写最终 commit；门禁改实际结果；在线建 PR；离线出最终改动包。「你要做的」→「待合并」。处理记录「实现时才发现」留给 R。

## 规则

结果原文不改，结论写处理记录。未执行标未执行；不用「本地核对」代替。

## 产出

`S3-01-结果-r{N}.md`、`S3-02-处理记录.md`、下一轮交付物。

## 出口

验证清单 100% 通过；门禁无「失败」；在线 PR 已建或离线终包已交。未收口前每轮「你要做的」符合当前位置对 S3 的要求。
