# S3 验证与修复

## 目标

每轮比上轮更接近「全部通过」。同一问题不跨两轮结果。

## 输入

本轮交付物、`S2-07`、本轮结果（自跑+带回）。

## 步骤

### 1. 执行与归档

「执行者」自跑；「verify」「手工」由执行人带回。原文存 `S3-01-结果-r{N}.md`。`S3-02` 加 r{N} 节，编号 A-01/B-01/C-01/D-01…。信息不够先处理能判的，缺的进下轮「请补充」。r1 带回编译/单测则回填 S2 门禁表。

### 2. 按类分流

遵守自我纠错。

| 类 | 动作 |
|----|------|
| **A 基线** | 不改码、不造远距增量。在线 rebase；离线：选表「其他」软回退打本包全量，仍败再快照刷新。下包只出全量。手册「环境」更新基线 |
| **B 编译/单测** | 逐条修。能静态查→加 precheck+selftest（编号记处理记录）。同类算一条。出包前再扫本轮改过文件同类用法 |
| **C 行为** | 先问题分类（安全/实现质量→`S2-08`「后续优化」，不阻塞）。判实现错或设计错，处理记录写一句理由（引 AC/D/位置）。实现错修码；设计错先改设计（`[S3 修订]`），口径变→待定，再修码。用户可推翻归因。不够信息不猜。连续两轮不过→自我纠错 |
| **D 环境事实** | 实际≠设计→回写 S2 sql/config/手册/常量 + 手册「登记占用」。影响口径→待定 |

### 3. 待定决策一次问

本轮新 `Q-xx` 按决策分级，攒齐一次发。必问未关相关代码不进下轮；其余修复不阻塞。

### 4. 交付下一轮

按 S2 步骤 3–9 出 r{N+1}（含自我纠错与找茬；触及已审查或需求不符→Step 7 复核）。现行终包移入 `_archived`，再生新终包。**B** 写本轮 `S3-02`，**A** 勾门禁；未过 A 不得更新「你要做的」。差异逐条引本轮编号。清单本轮列：失败重跑+受影响+尚未执行。

三处同文须「S3 短清单」（当前位置）。缺表/粘回/缩写、本轮改过未入步骤、步骤内长文/嵌套=未交付完。数据污染先跑 `reset_test.sql`。

### 5. 收口

清单全过：手册「代码」写最终 commit；门禁改实际结果；在线建 PR；离线出最终改动包。「你要做的」→「待合并」。处理记录「实现时才发现」留给 R。

## 规则

结果原文不改，结论写处理记录。未执行标未执行；不用「本地核对」代替。

## 产出

`S3-01-结果-r{N}.md`、`S3-02-处理记录.md`、下一轮交付物。

## 出口

验证清单 100% 通过；门禁无「失败」；在线 PR 已建或离线终包已交。未收口前每轮「你要做的」符合当前位置对 S3 的要求。
