# S0 项目手册

## 目标

一份 `artifacts/_project/S0-01-项目手册.md`，让任意需求 S1 开工 10 分钟内知道：代码在哪、哪些仓不能乱改、公共机制怎么用、某类功能参照谁、构建环境怎样。

不是代码基线。只记「用过两次以上、以后还会用」的事实。

## 什么时候做

| 时机 | 做什么 |
|------|--------|
| 首次 | 不问用户：按模板建，**只填本需求会碰到的仓与机制**（仓库地图可全列）；其余「待回填」。环境由 S1 选项+S2 Step 0 实测填。正确性靠后续走读以代码纠正 |
| S1 走读 | 稳定事实当场回填 |
| R 复盘 | 「实现时才发现」回填；「回填记录」加一行 |
| 环境变化 | 更新基线 commit、依赖同步状态 |

## 规则

1. 每条带出处：`路径:行` 或 `路径#方法`。无出处不写。
2. 写「怎么用」，不写「有什么」。
3. 手册与代码不符→以代码为准，改手册并标日期。
4. 不写需求专属内容；占用记「登记占用」供并行避让。
5. 「平台登记清单」=取样与上线前核对依据；从已有上线手册/导出倒推，按本项目写。
6. 「术语映射」=业务词→字段/字典项；S1 遇新词当场查清回填。
7. 超 300 行时参照索引拆独立文件，手册留链接。

## 产出

`S0-01`（结构见同目录模板）；`S0-02-precheck.json`（项目级：`api_prefixes`/`table_prefixes` 覆盖全仓；`fe_aliases`；`ref_dirs`；`identity_fields`；`project_terms`）。

## 出口

- 本需求 S1 要用的章节（至少：仓库地图、共享边界、相关公共机制、相关参照）有内容且出处可开。「你要做的」写「无」。
- 「环境」基线 commit 与构建当前分支一致（S2 Step 0 确认）。
