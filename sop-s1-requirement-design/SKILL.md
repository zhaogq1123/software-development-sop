# S1 需求与设计

## 目标

一次写清做什么、照谁做、数据从哪来、怎么验收演示；S2 不再回头问设计。用户在写码前就能按剧本走查。

## 输入

原文经 `precheck.py --ingest` → `S1-00-原文/正文.md`。清单待看/无法看则不出口。另有 `S0-01`、代码。

## 步骤

### 0. 判断类型

按「按需求类型裁剪」写入 `00-当前位置`。小改动/缺陷/纯配置→`S1-07`（含短剧本）；新功能走全套。

线上缺陷：先复现定位到 `文件:行`；复现不了→待定。

### 1. 决定表

有行为含义的句子→`D-xx`。矛盾进待定。原文没写的**业务行为**=必问；**技术细节**=照先例。

### 2. 需求与验收

`D-xx`→`REQ`+`AC`。AC=能操作能看见结果。写不出→待定。

### 3. 参照代码走读

跟完整链记接触点（仿/改/新建）。复用接口读到实现。共享仓/多实现按共享边界。给交付选项建议。

### 4. 平台登记数据取样

能取则取；取不到写「上线前核对」。机制是否存在不清→待定。

### 5. 设计说明（含验收走查材料）

写接口/表/状态机/缓存/错误码/共享边界/上线清单草稿，以及（见产出模板）：

1. **路径矩阵**：模式或角色 × 动作 → 本期走通 / 本期不做（表现方式）/ 待定。
2. **验收剧本**：步骤、点什么、期望看见、数据从哪来（已知写出处；未知→Q）。
3. **流程图**：主路径 mermaid（`flowchart` 或 `sequenceDiagram`）；多数据源/多模式/本期预留时建议另出 `S1-06`。

- 字段/出参追到 AC 或 D；追不到不建。
- 接口写清调用者/数据范围/状态前置（需求管控；审查按此判需求不符）。
- 业务术语用代码证据定到字段/字典；一致→手册「术语映射」；冲突/找不到→必问。禁「待联调核对」（T1）。

规则（生命周期 › 决策）：

- 数据来源/查询键/查不到算什么未关闭 → 不写识别实现，对应改动面不列。
- `本期不做`：藏入口或明确文案；**禁止**为拦截去查另一业务域（无已关闭 D 时）。
- 改动面从走读「改/新建」得出；「验证」列写 AC-xx；剧本确认后再请「确认改动面」才是 S2 清单（C1/C2）。

写完自我纠错。

### 6. 待定决策，一次问齐

必问给建议值与「按建议会怎样」；逐条确认须逐条回。回复→`D-xx`；未回不出口。

### 7. 评审（两拍）

1. 必问已关后：发剧本+路径矩阵+图 → 用户「剧本确认」或指出路径（当前位置「S1 待走查」）。
2. 剧本确认后：发改动面 →「确认改动面」（「S1 待评审」）。勿在必问未关或剧本未确认时请确认改动面。

## 规则

- 不编造。未读到实现的接口不许「复用」。
- 不改共享仓是建议值；要改走共享边界。
- 不写 PRD；对接文档/冒烟在 S2 按选项产。

## 产出

新功能：`S1-01`…`S1-05`（可选 `S1-06`）。其他：`S1-07`。

## 出口

- 必问无待定；交付选项有用户选择（D1）。
- 用户已「剧本确认」且「确认改动面」。
- 复用接口读到实现；登记有取样或上线前核对；术语已映射。
- 剧本中「待定」路径无对应实现行进改动面。
