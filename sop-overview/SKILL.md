# sop-overview

本目录是 sop-v2 的总纲，各阶段 skill 引用的章节都在这里：

- [生命周期.md](生命周期.md)：阶段与出口、门禁与证据、问题分类、指标、按需求类型裁剪、需求变更、环境形态、验证循环、合并与发包、当前位置（含你要做的）、决策、单一真相源、共享边界、不做的事。
- [环境准备.md](环境准备.md)：让本机能编译、离线快照的代码刷新。
- [SOP约束.md](SOP约束.md)：修改 sop-v2 本身时的硬约束（只写通用流程、篇幅上限、增删规则、lint）。

## 该用哪个 skill

建或回填手册 `sop-s0-project-handbook`；拿到需求、缺陷、配置数据变更 `sop-s1-requirement-design`；改动面确认后写代码出包 `sop-s2-implement-deliver`；收到编译、用例、部署结果 `sop-s3-verify-fix`；上线完成 `sop-r-retrospective`。

## 开工前先读

1. `artifacts/{需求}/00-当前位置.md`（有则按它继续；无则从 S1 开始，S0 手册不存在则先建）。
2. `artifacts/_project/S0-01-项目手册.md`。
3. 本目录 `生命周期.md`「门禁与证据」「问题分类」「按需求类型裁剪」「当前位置」「决策」。

每个阶段开一个新会话，只靠 `00-当前位置.md` 和 `artifacts/` 接续，不依赖上一会话的记忆。其中「你要做的」是给用户的，对话最后一条与它一致。

## 三条总规则

1. skill 只写通用流程，项目与需求专有内容进项目手册、`precheck.json` 或需求产物（SOP约束 › 只写通用流程）。
2. 一个事实只存一处，其他地方引用编号（`D-xx`、`REQ-xx`、`AC-xx`、`Q-xx`）。
3. 门禁见 生命周期 › 门禁与证据，每项如实记「通过 / 失败 / 无法证明」；执行者自评和自造的验证不算证据。
