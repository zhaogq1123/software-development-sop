# 可选加速项（不是前提）

开箱即用不需要本文件。首次从 S0 起，执行者自建手册首版；环境形态由用户在 S1 交付选项选。此处只列「做了能少一轮验证」的事，以及离线快照刷新代码的做法。

## 让本机能编译

S2 Step 0 补偿后仍不通时提示本项。在能编译机器上把依赖下到本地缓存（后端仓库、前端目录、父构建），打包拷到本机对应位置，工具链主版本一致。命令写入手册「环境」。

同步后告知执行者「依赖已同步」；实测一次离线编译后，编译即硬门禁。

## 代码快照刷新

仅离线快照（能 fetch 真实仓则直接 rebase）。无共同历史→不 rebase，重导+重放：

1. 真实仓机器导出涉及仓（`git archive` 或打包），拷到本机。
2. 导入为快照新提交（覆盖子目录，信息「快照 {日期}」）。
3. 从新快照切 `feature/{需求}-r{N}`，按子目录 `--3way` 重放上轮 patch，冲突就地解决并提交。
4. 重跑 precheck 出新 patch；手册「环境」更新快照日期。

触发：S2 Step 0 答「快照后有新提交」，或软回退后全量仍因基线漂移失败。

## 用户侧软回退（与快照刷新分工）

真实仓叠多轮、状态不清、或 apply 失败，但快照基线仍准：勿打远距增量。丢弃 `feature/{需求}` 上本需求改动（或新建分支），回到 README 记载基线，只打当前终包 `patches/` 全量（选择表「其他」）。

软回退=用户侧；快照刷新=执行者侧重导。先软回退，仍败再刷新。
